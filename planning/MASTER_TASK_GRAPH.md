# Master Task Graph

## Purpose

This is the compact program index. The milestone documents contain the full task packets and are authoritative for deliverables, acceptance criteria and fast gates. Agents update status in `agents/WORK_QUEUE.md` and durable machine state; they do not rewrite completed task history here.

## Status values

`planned` → `ready` → `claimed` → `in-progress` → `in-review` → `merge-queued` → `complete`; exceptional states are `blocked`, `waived`, and `superseded` with evidence/authority.

## Orchestrator rules

- Readiness is determined by `planning/DEFINITION_OF_READY.md` and merged dependency evidence.
- Select the highest-impact unblocking ready task, then a non-overlapping second-lane task.
- Shared contracts are serialized before dependent implementations.
- A task reaches `complete` only under `planning/DEFINITION_OF_DONE.md`.
- M9 begins only after an immutable release candidate and independent readiness review.
- Final project status becomes `COMPLETE` only after M9-T12 and accountable approvals.
