## API-verification deviations from the design doc

The design doc was written before M2-T05's builder incorporated live
security-review feedback. Reading `crates/dom/src/**` directly (not
assuming the design doc's guessed shapes) surfaced three places where this
task's implementation had to diverge from the design's literal text:

1. **No `NodeIndex` accessor exists; the design's §0 coordination note asks
   for one.** `machina_dom::handle::NodeIndex` is `pub(crate)` to
   `machina-dom`, and `NodeHandle` exposes no `.index()` method. Per this
   task's explicit instruction ("do not edit `crates/dom`... document the
   gap instead"), no accessor was requested. **Resolution:** the listener
   table is keyed by the full `NodeHandle` (`HashMap<NodeHandle, Vec<...>>`)
   instead of a bare `NodeIndex`. This is functionally equivalent for this
   crate's purposes: within one `EventTargetRegistry` (always scoped to one
   `DocumentId`), a live node's `NodeHandle` never changes for its entire
   lifetime — the generation component only advances when a slot is *reused*
   for a different node, which only happens after
   `EventTargetRegistry::handle_node_freed` has already removed that node's
   old entry. See `crates/events/src/target.rs`'s module doc comment for the
   full reasoning. No `crates/dom` change was requested or made.
2. **The `WrapperObserver` hook methods take `&self`, not `&mut self`, and
   fire from *inside* an already-in-progress `&mut Document` mutation call.**
   The design's §3 describes three hooks "matching `WrapperObserver`'s
   signatures verbatim... so the composing owner's single observer impl can
   simply forward." A literal forward is only possible for the two hooks
   that fire no events (`handle_node_freed`, `handle_document_teardown`,
   both implemented with the exact `WrapperObserver` parameter list).
   `handle_node_changed` is different: firing `blur`/`focusout` requires
   `&mut Document`, which is provably unavailable at the point
   `Document::notify_changed` invokes `on_node_changed(&self, ...)` (Rust's
   borrow checker forbids a second `&mut Document` while the mutation
   method's own `&mut self` is still on the call stack, and re-entering the
   same document mid-mutation would be unsound even if it compiled).
   **Resolution:** `EventTargetRegistry::handle_node_changed` takes an
   explicit `&mut Document` parameter the *composing owner* supplies once
   the top-level mutation call has returned (buffering the raw
   `(handle, change)` notification in the interim — the same pattern
   `crates/dom`'s own test-only `RecordingObserver` already uses via
   `Arc<Mutex<Vec<_>>>`). Documented in the method's doc comment in
   `crates/events/src/target.rs`, with the exact required wiring shape
   spelled out for whichever task first composes the real observer (see
   "Deferred / left for a later task" below).
3. **`EventListener: Send` (from the design's §1) was dropped.** Listener
   storage snapshots callbacks as cheap clones so dispatch can hand a
   listener mutable `Document`/`EventTargetRegistry` access without holding
   a live borrow of the table across the call (see "Snapshot mechanism"
   below). `Rc<dyn EventListener>` was used for this, not `Arc`, because
   `machina_dom::Document` is already documented as single-thread-at-a-time
   and this crate's own test listeners need ordinary (non-atomic) interior
   mutability (`Cell`/`RefCell`) to record call order — a `Send + Sync`
   bound would have forced `Arc` and blocked that ergonomic pattern for no
   real benefit. Documented in `crates/events/src/listener.rs`'s
   `EventListener` doc comment.

None of these three changed any public *behavior* the design specifies —
only the internal storage key and two trait/method signatures.

## Snapshot mechanism (why listener mutation mid-dispatch is safe)

`Rc<dyn EventListener>` (not `Box`) is the callback storage type
specifically so that, for each node's turn in the capture/target/bubble
loop, `EventTargetRegistry::snapshot_listeners` can produce an **owned**
`Vec<ListenerEntry>` (cheap `Rc::clone`s, not borrows of the registry)
before invoking any of that node's listeners. This is what lets a listener
receive a `&mut Document`/`&mut EventTargetRegistry` (via
`DispatchContext`) during its own invocation — the dispatch loop is not
holding any live borrow of either at that point, only the pre-cloned
snapshot. This is the mechanical basis for every "add/remove/mutate
mid-dispatch" acceptance test in `tests/dispatch_order.rs` and
`tests/click_action.rs`.

## Implemented

- **Listener storage** (`target.rs`): `EventTargetRegistry` — per-document
  (`DocumentId`-checked on every call), `HashMap<NodeHandle, Vec<ListenerEntry>>`,
  idempotent `add_event_listener` (linear scan on
  `(event_kind, capture, identity)`, matches real
  `EventTarget.addEventListener` re-add semantics), `remove_event_listener`
  (by identity triple) and `remove_event_listener_by_id` (by the returned
  handle), `listener_count` diagnostic.
- **Dispatch algorithm** (`dispatch.rs`): `dispatch_event` builds the
  root-to-target ancestor path once (bounded by
  `machina_dom::MAX_ANCESTOR_WALK`, reusing the same public constant
  `crates/dom` exports), then walks capture (root→parent-of-target,
  `capture:true` only) → at-target (both capture flags, registration order)
  → bubble (parent-of-target→root, `capture:false` only, skipped if
  `!bubbles`). Each node is re-validated (`document.node(node).is_ok()`)
  immediately before its turn — a stale/freed node is skipped gracefully
  (`DispatchOutcome.fully_completed = false`), not a hard error. Per-node
  listener snapshots make add/remove-during-dispatch spec-correct (see
  "Snapshot mechanism"). `once` listeners are removed right after
  invocation; `passive` listeners run with `in_passive_listener = true` so
  `prevent_default()` silently no-ops. `stop_propagation()` finishes the
  current node's remaining listeners, then halts before the next node;
  `stop_immediate_propagation()` also halts the current node's remaining
  listeners. `Event::composed_path()` returns the dispatch-start path
  snapshot (target-first, spec order), immune to mid-dispatch tree
  mutation.
- **Focus model** (`focus.rs`): `focus`/`blur` free functions taking
  `&mut Document`/`&mut EventTargetRegistry`. `focus` is a no-op if already
  active; otherwise sets the active element *before* firing any event
  (deliberate, matches the design's documented Chromium-observable
  ordering), fires `blur`+`focusout` at the old element (skipped if it no
  longer resolves), then `focus`+`focusin` at the new one. `blur` fires
  `blur`+`focusout` while the old element is *still* active, then clears —
  the opposite order from `focus`'s transition case, exactly as the design
  specifies, with a dedicated test proving both orderings via a listener
  that reads `registry.active_element()` mid-dispatch.
  `is_focusable_by_default`/`nearest_focusable` implement the minimal
  focusability rule (parseable `tabindex`, or `button`/`input`/`select`/
  `textarea`/`iframe` unconditionally, or `a`/`area` with `href`).
- **DOM-lifecycle interop hooks** (`target.rs`):
  `handle_node_changed`/`handle_node_freed`/`handle_document_teardown` —
  see "API-verification deviations" #2 for the one signature change from a
  literal `WrapperObserver` forward.
- **Synthetic click** (`action.rs`, `mouse.rs`, `keyboard.rs`):
  `MouseEventInit`/`MouseButton` (used) and `KeyboardEventInit` (typed,
  constructible, intentionally unused by this task — forward-compat for a
  future `interaction.type.v1`). `perform_click` — narrow interactability
  precheck (`is_attached`, exported from `dispatch.rs`), then
  `mousedown → (implicit focus, unless prevented) → mouseup → click`,
  re-validating the target before each dispatch step and reporting a
  `PostconditionState::Failed(reason)` (not a panic, not a silent partial
  success) if a listener frees it mid-sequence.
