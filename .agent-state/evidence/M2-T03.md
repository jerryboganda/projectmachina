## What was implemented (the crate's actual logic, not a stub)

- **Tokenizer state machine** (`src/state.rs`, `src/tokenizer.rs`): a flat
  `State` enum (77 variants) covering WHATWG HTML §13.2.5's state groups —
  text-content modes (Data/RCDATA/RAWTEXT/ScriptData/Plaintext), tag open/
  name, the 12-state script-data escaping subgroup (single- and double-
  escape start/end, dash/dash-dash chains), attributes (dedup first-wins),
  comments (including the `<!--<!--` nested-comment and `<script>`-inside-
  comment edge cases), DOCTYPE (name/PUBLIC/SYSTEM identifiers), a foreign-
  content CDATA section, and character references. `Tokenizer::next_event`
  is a single non-recursive driver: `step()` consumes at most one input
  character per call, with all working state (in-progress tag/comment/
  doctype, character-reference scratch, the pending character run) living
  in `Tokenizer` struct fields, never the Rust call stack — this is what
  makes the streaming/pause-resume behavior below fall out structurally
  rather than needing bespoke logic, exactly per design §1/§3.
- **Character reference decoding** (`src/entities.rs`, `src/tokenizer.rs`):
  numeric (`&#NNN;`/`&#xHHHH;`) references fully implemented per spec,
  including the fixed 26-entry C1-control remapping table, surrogate/
  noncharacter/out-of-range/null handling, and saturating arithmetic (no
  overflow panic path). Named references use longest-prefix matching over
  a static table with legacy-no-semicolon-required tracking — see "Entity
  table scope" below for exactly what subset shipped.
- **Streaming/chunk-boundary handling** (`src/input.rs`): `InputStream`
  holds up to 3 carry bytes across `feed()` calls for incomplete UTF-8
  sequences (never dropped, never guessed), decode diagnostics are queued
  in-line with the characters they relate to (not returned eagerly, so
  they interleave correctly with the tokenizer's lazy pull-based
  processing), and CRLF/lone-CR normalization is chunk-boundary-safe via a
  single `pending_cr` byte held across `feed()` calls.
- **The public pull API and external state-switch hook** (`src/lib.rs`,
  `src/tokenizer.rs`) matches design §7 exactly: `Tokenizer::{new, feed,
  finish, switch_to, last_start_tag_name, next_event}`,
  `Token::{Doctype,StartTag,EndTag,Comment,Character,Eof}`,
  `TokenizerEvent::{Token,Diagnostic}`. `next_event`'s loop structure
  (drain the event queue before ever reading another input character)
  guarantees a caller's `switch_to` call after observing a `StartTag`
  takes effect before the next byte is scanned — verified directly by the
  RCDATA/RAWTEXT/ScriptData tests in `tests/state_coverage.rs`, which call
  `switch_to` from inside the event-draining loop exactly as the tree
  builder (M2-T04) will.
- **Bounded-input limits** (`src/limits.rs`, `src/tokenizer.rs`): all 9
  fields from design §4's table implemented with their documented recovery
  action (truncate-and-continue, cap-and-discard, forced-flush, or
  force-terminate-and-resync-to-Data for the byte-span backstop), each
  raising exactly one `LimitExceeded` diagnostic per construct (not one
  per byte). `max_diagnostics_buffered` coalescing is implemented and
  tested. No `unwrap`/`expect`/`unsafe`/unchecked-truncating-cast anywhere
  in `src/` reachable from external input (the crate is
  `#![forbid(unsafe_code)]`; the one narrowing cast, `len as u8` in
  `input.rs`, is bounded immediately beforehand by `.min(3)`).

## Entity table scope — the deliberate MVP reduction (read this first)

Per the task's explicit scoping instruction, the full ~2231-entry WHATWG
named-character-reference table was **not** vendored in this pass. Instead:

- **63 named entities** were curated by hand (the highest-frequency ones:
  `amp`/`lt`/`gt`/`quot`/`apos`/`nbsp`/`copy`/`reg` and case variants, common
  punctuation, a handful of Latin-1 accented letters, and common math/arrow
  symbols — see `crates/html/src/entities.rs`'s `ENTITY_TABLE` for the exact
  list).
- Real internet access **was** available in this sandbox. The 63 entries'
  *values* were fetched from the real, currently-published WHATWG table
  (`https://html.spec.whatwg.org/entities.json`, fetched 2026-08-09,
  `Last-Modified: 2025-11-12`) and are not hand-typed from memory — only the
  *set* of which 63 entries to curate is a hand judgment call, consistent
  with the task's "vendor a small, clearly-licensed subset" instruction.
  Full provenance (URL, fetch date, response headers, license — WHATWG's
  `LICENSE`: CC BY 4.0, BSD-3-Clause for the source-code-incorporated
  portion) is recorded in `crates/html/data/PROVENANCE.md`. The raw
  145,897-byte `entities.json` itself was **not** committed — only the
  derived 63-entry Rust table.
- The matching **algorithm** (longest-prefix scan with per-character
  narrowing, legacy-no-semicolon handling, multi-character pushback for a
  shorter match nested inside a longer scanned prefix) is fully general and
  does not need to change if the table grows later — verified by
  `entities::tests::prefix_matching_supports_a_synthetic_nested_table`,
  which exercises the nested-prefix pushback path with a synthetic table
  since the shipped 63-entry table happens to contain no such pair
  (`entities::tests::shipped_table_has_no_nested_prefix_pairs` documents and
  proves that fact structurally rather than leaving it an unstated
  assumption).
- **Consequence**: any named entity outside the 63 shipped falls through to
  the "unknown named character reference" path — the literal `&name;` text
  is preserved (not dropped), with a diagnostic when the scanned name looked
  syntactically complete. This is a real content gap versus a spec-
  conformant browser and is the first thing that must be closed before any
  WPT `namedEntities.test`/`entities.test` run could pass.

This is the single most consequential scope reduction in this task and is
being surfaced explicitly, not silently — see "Deferred heavy validation"
below for how it's tracked.

## Deliberate behavioral simplifications (documented, not spec-exact)

These are implementation choices made for time/scope reasons in this pass;
none of them affect the streaming-equivalence or bounded-input acceptance
criteria, and all are covered by my own tests exercising the *actual*
shipped behavior (not a spec-exact behavior I haven't verified):

- NUL handling is uniformly "replace with U+FFFD + diagnostic" in every
  text-producing context (Data/RCDATA/RAWTEXT/ScriptData/attribute values),
  rather than the WHATWG spec's Data-state-specific "keep the literal NUL"
  carve-out.
- The named-character-reference attribute-context ambiguous-`=`/alnum
  disambiguation (spec's specific historical carve-out for e.g. `&notin=5`
  inside an unquoted attribute value) is not implemented; this tokenizer
  always substitutes on a legacy/complete match regardless of return-state
  context.
- CDATA sections (`<![CDATA[...]]>`) are recognized unconditionally
  wherever `<![CDATA[` appears, rather than being gated on "current node is
  in a foreign-content (SVG/MathML) namespace" — that gating is tree-builder
  context the tokenizer alone doesn't have. M2-T04 can add a
  `set_cdata_allowed`-style toggle later if needed; documented here so it
  isn't a silent behavior gap.
- WHATWG's dedicated "ambiguous ampersand state" is folded into
  `NamedCharacterReference`'s finalization rather than kept as a literal
  extra state that re-scans trailing alphanumerics before deciding whether
  to raise `UnknownNamedCharacterReference` — content output is identical
  either way; only the diagnostic firing is slightly less precise (documented
  in `src/state.rs`).

## Acceptance criteria mapping

- **"Priority tokenizer fixtures pass"** — 31 hand-written fixtures in
  `tests/state_coverage.rs` covering tags/attributes/dedup, comments
  (including abrupt-close and nested-`<!--`), DOCTYPE (simple, case-
  insensitive keyword, PUBLIC+SYSTEM, missing-name force-quirks), RCDATA vs.
  RAWTEXT vs. ScriptData (including the escaping and double-escaping
  subgroups round-tripping literally), named references (with/without
  semicolon, legacy vs. non-legacy, unknown), numeric references (decimal,
  hex, null, C1-control remap), CDATA, and EOF-in-construct recovery. All
  pass. **Caveat**: these are my own fixtures, not the vendored WPT/
  html5lib-tests corpus — see "Deferred heavy validation".
- **"Arbitrary chunk boundaries produce an equivalent token stream"** — the
  one criterion explicitly required not to be shortcut.
  `tests/chunk_boundary_equivalence.rs` splits 10 representative documents
  (tags/attributes/comments/DOCTYPE/entities/CRLF/RCDATA/script-double-
  escape/CDATA/NUL) at **every possible two-way byte offset**, plus a
  46-way and ~180-way multi-split, plus true byte-at-a-time feeding of a
  larger combined document, plus dedicated multibyte-UTF-8-boundary and
  mid-entity-name-split cases, and asserts the resulting token stream is
  equivalent (identical non-`Character` tokens; `Character` tokens
  equivalent at the concatenated-text level, per design §3's formal
  contract). It also directly tests the one sanctioned exception
  (`max_character_run_len` forcing a content-driven, chunk-boundary-
  independent flush point) and proves the flush point's reconstructed text
  is chunk-boundary-independent even though the exact token count can
  legitimately vary. All pass.
- **"Adversarial input remains bounded and crash free"** —
  `tests/bounded_limits.rs` exercises all 9 `TokenizerLimits` fields with
  deliberately small limits (oversized tag name/attribute count/attribute
  value/comment/doctype field, forced character-run flush, the byte-span
  backstop firing when only the aggregate is oversized, the named-char-ref
  scan-step cap, and diagnostics coalescing past the cap), asserting the
  documented recovery action, the corresponding diagnostic, and — critically
  — forward progress afterward (well-formed markup following the
  adversarial construct still parses correctly, proving the tokenizer
  resynced rather than got stuck). `tests/no_panic_fuzz_lite.rs` adds a
  dependency-free, fixed-seed randomized smoke test (3000 HTML-alphabet-
  biased random documents, 500 arbitrarily-chunked random documents, 2000
  fully-arbitrary-byte-including-invalid-UTF-8 documents) asserting no
  panic and clean termination to `Token::Eof` in every case, plus an
  explicit infinite-loop guard (a 1,000,000-iteration assertion) as a
  structural belt-and-suspenders check on top of the architectural
  non-recursion guarantee.
- **"Incremental tokens and parse diagnostics without panics"** —
  `next_event`'s pull API is exercised throughout every test above;
  `#![forbid(unsafe_code)]` plus the absence of `unwrap`/`expect` in
  `src/` (grep-verified, see Fast gate below) backs the "without panics"
  half structurally, not just by absence of observed failures.
