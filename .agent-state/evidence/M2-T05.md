## Implemented

- **Storage**: one `Document` = one `NodeArena` (`Vec<Slot>` + free list) =
  one generation space = one teardown unit. Tree edges are `Option<NodeHandle>`
  fields (`parent`/`first_child`/`last_child`/`next_sibling`/`previous_sibling`)
  on each node, not per-node `Vec<child>` storage.
- **Handles**: `DocumentId` (process-unique `AtomicU64`), `NodeIndex`,
  `Generation`, `NodeHandle`, and kind-typed `ElementHandle`/`TextHandle`/
  `DocumentFragmentHandle`/`DocumentTypeHandle` (all `Copy`, produced only via
  a checked constructor or `Document::as_*` downcast). `Document::resolve`/
  `resolve_mut` are the single choke point: wrong-document, then
  document-closed, then stale-generation/freed-slot (via `NodeArena`, always
  `Vec::get`/`get_mut`, never index syntax) — every path returns a typed
  `DomError`, never panics.
- **Core API**: `create_element`/`create_element_ns`/`create_text`/
  `create_comment`/`create_document_fragment`/`create_document_type`,
  `node`/`as_element`/`as_text`/`as_document_fragment`/`tag_name`/
  `element_namespace`/`attribute`/`text_data`/`children` (reads),
  `insert_before`/`append_child`/`remove_child`/`replace_child`/
  `adopt_node`/`clone_node`/`destroy_node` (mutation), `set_attribute`/
  `remove_attribute`/`set_text_data`, `revision`/`memory_usage`/
  `set_wrapper_observer`/`close`.
- **Two-phase mutation**: every mutating method validates fully (read-only)
  before any write; commit-phase link manipulation (`detach_internal`/
  `splice_before`/`link_append`) always re-resolves live links rather than
  acting on validate-phase-cached positions.
- **Interning**: static compiled-in table (`OnceLock`, ~60 well-known
  tag/attribute names) plus a per-document dynamic `StringInterner`, dropped
  with the document. `memory_usage()` includes the dynamic interner's bytes
  (fixed during implementation — the first draft only tracked node/attribute
  bytes and left the interner's own growth unaccounted, which would have
  undercounted adversarial custom-tag growth).
- **Revision**: one monotonic `u64` counter per document, bumped once on
  every successful call that actually changes something (including
  creation); unchanged on `Err` and on the two genuine no-op cases
  (`replace_child(p, x, x)`, `remove_attribute` of an absent attribute).
- **`WrapperObserver`**: single slot, `on_node_changed(handle, NodeChange)`/
  `on_node_freed(handle)`/`on_document_teardown(document)`, `Send` not
  `Sync`. `NodeChange` has one extra variant beyond the design doc,
  `Adopted { previous }` — see "Security review" below.
- **Teardown**: idempotent `Document::close()` (fires `on_document_teardown`
  once, replaces the arena, zeroes counters) plus `Drop for Document` calling
  `close()` unconditionally, so scope-drop without an explicit call still
  tears down correctly and still fires teardown exactly once.

## Deviations / extensions beyond the design doc, and why

1. **`Document::destroy_node`** (new, not in the original design's API
   list) — added per the security review's headline finding (below). This
   is the crate's only genuinely new public method beyond that finding.
2. **Generation widened to `u64`** (design implied a compact "20-byte"
   handle, i.e. `u32` generation) — per the security review, below. Handle
   is now 24 bytes, not 20.
3. **`Namespace`, `create_element_ns`, `element_namespace`,
   `DocumentTypeHandle`, `create_document_type`** — added mid-implementation
   at the request of the M2-T04 (tree builder) design, which depends on
   both for SVG/MathML foreign content and DOCTYPE construction.
   `create_element` is now sugar for `create_element_ns(Namespace::Html,
   tag)`; both `create_element`/`create_element_ns` and
   `create_document_type` are now `Result`-returning (reject an
   empty/whitespace-only name via `DomError::InvalidName`) where the design
   doc did not specify fallibility for `create_element`.
4. **`DomError` gained three variants** beyond the four the design doc names
   explicitly (`WrongDocument`/`HierarchyViolation`/`NotFound`/
   `SameDocument`): `StaleHandle`, `DocumentClosed`, `WrongKind` (all
   explicitly implied by the design's prose, just not listed as named
   variants), plus `DepthLimitExceeded`, `NodeStillAttached`,
   `NodeHasChildren`, `InvalidName` (new, for the extensions above).
5. **`MAX_ANCESTOR_WALK` is a public constant set to `100_000`** — the
   design named the constant but left its value and its exact scope
   (fuzz-hardening vs. cycle-detection) unstated; resolved per the security
   review, below.
6. **`adopt_node(self, self) -> SameDocument` is not exercisable from
   outside the crate.** `Document::adopt_node(&mut self, source: &mut
   Document, ...)` requires two independent `&mut` borrows; calling it with
   `self`/`source` as the same binding is a compile error (E0499) before the
   runtime check is ever reached. This makes "adopt_node cannot move a node
   within the same document" a *compile-time* guarantee, strictly stronger
   than a runtime one. The `DomError::SameDocument` variant and the `if
   source.id == self.id` check are kept as defense-in-depth documentation
   of the invariant (harmless if the signature is ever refactored), but the
   specific runtime-error test the design doc's test plan names is not
   constructible in safe Rust; `tests/mutation_invariants.rs` documents this
   reasoning in a code comment instead of a fabricated test.
7. **Document child relative-ordering (DocumentType before Element) is not
   enforced.** Matches the security review's own low-priority assessment
   (finding 5b): `Document` only enforces "at most one Element child" and
   "at most one DocumentType child" independently, not their relative
   order. Low risk since M2-T04's parser is expected to always insert
   correctly; recorded here as a named, intentional limitation rather than
   left silently absent.

## Security review — how each finding was addressed

An independent review (`.agent-state/design/M2-T05-security-review.md`) of
the design landed mid-implementation. Every finding was incorporated in
source in this same pass, not deferred:

- **Finding 1 (generation wraparound, silent aliasing)**: `Generation`
  widened `u32` -> `u64` (see deviation 2). Wraparound is now astronomically
  unreachable rather than reachable within a multi-day soak run.
- **Finding 2a (descendant-handle staleness after adopt not tested)**:
  added `tests/handles.rs::adopt_node_stales_every_descendant_handle_not_just_the_moved_root`,
  which asserts both the moved root's *and* its child's handle go stale in
  the source document.
- **Finding 2b (adopt_node can't preserve JS object identity)**: **not
  fixable within this crate's scope** — the free-and-recreate design is
  structural, not a bug. Documented as a named, forward-flagged limitation
  in `adopt_node`'s doc comment for M2-T06/T07, and mitigated with a new
  `NodeChange::Adopted { previous: NodeHandle }` observer event (fired on
  the new handle, carrying the old one) so a future wrapper cache can re-key
  instead of only seeing an unrelated free+create pair.
- **Finding 3a (self-aliased arguments risk corrupted links)**: fixed with
  two explicit guards — `insert_before` returns `Ok(())` immediately if
  `reference == Some(new_child)` (would otherwise splice a node before
  itself), and `replace_child` special-cases `new_child` being `old_child`'s
  existing next sibling (would otherwise do the same). Both are covered by
  dedicated tests
  (`insert_before_a_node_immediately_before_itself_is_a_safe_no_op`,
  `replace_child_with_its_own_next_sibling_does_not_corrupt_the_sibling_list`).
  All commit-phase link steps (`detach_internal`/`splice_before`/
  `link_append`) re-resolve live links rather than using validate-phase
  snapshots.
- **Finding 3b (clone_node depth-guard timing/orphaned-slot leak)**:
  `collect_subtree` is a strictly read-only pass over the source with its
  own depth check; `materialize` (destination allocation) is only ever
  called after `collect_subtree` returns `Ok`, and is now infallible (no
  redundant/inconsistent depth re-check on the destination side). Covered
  by `depth_bound_fails_closed_for_ancestor_walk_and_deep_clone_without_leaking_memory`,
  which asserts `memory_usage()` is byte-for-byte unchanged after a
  rejected deep clone.
- **Finding 3c (replace_child false-positive on "<=1 Element child")**:
  `validate_new_child`'s cardinality check takes an `ignore` list that
  excludes both `new_child` and `old_child`, so replacing a document's sole
  Element child with a different Element is accepted. Covered by
  `replace_child_swapping_the_documents_sole_element_child_for_a_different_element_succeeds`.
- **Finding 4 (headline: no reclaim path for detached-abandoned nodes)**:
  added `Document::destroy_node` (see deviation 1); valid only on a
  currently-detached, childless node, fires `on_node_freed`, and refuses
  (`NodeStillAttached`/`NodeHasChildren`) otherwise. Covered by
  `tests/teardown.rs::destroy_node_reclaims_a_detached_childless_node_and_notifies_on_node_freed`
  and `destroy_node_refuses_a_node_that_still_has_children`.
- **Finding 4′ (adopt_node subtree free should fire N events, not batched)**:
  `adopt_node` frees each source-document slot individually via
  `NodeArena::free` in a loop, firing `on_node_freed` per node. Covered by
  `tests/teardown.rs::adopt_node_frees_every_subtree_slot_individually_not_as_one_batched_event`.
- **Finding 5a (`MAX_ANCESTOR_WALK` unstated/conflated)**: set to a
  documented, generous `100_000` (traversal is always iterative, so the
  bound only needs to guard total work, not call-stack depth). Covered by
  `legitimate_very_deep_non_cyclic_insert_is_not_falsely_rejected` (a real
  ~50,000-deep, non-cyclic insert succeeds) and the depth-bound test above
  (a >100,000-deep insert/clone fails closed with `DepthLimitExceeded`).
- **Finding 5b (child ordering not enforced)**: documented as an
  intentional, named limitation (deviation 7 above), matching the review's
  own low-priority assessment.
- **Finding 5c (verify "belongs to parent" is O(1))**: confirmed by
  inspection — every "does X belong to parent Y" check in `mutation.rs`
  (`insert_before`'s reference check, `remove_child`, `replace_child`) reads
  the child's own `links.parent` field directly (`data.links.parent !=
  Some(parent)`), never an O(children) sibling scan.
- **Finding 5d (false alarms)**: no action — `Revision`/`DocumentId` `u64`
  wraparound, generation-0/never-allocated-slot aliasing, and
  observer-reentrancy were confirmed already closed by construction, and a
  reentrancy test was added anyway for direct evidence
  (`tests/observer.rs::observer_callback_can_reentrantly_read_its_own_state_because_document_needs_no_interior_mutability`).

## Acceptance mapping

- **Stale/cross-document handles fail safely**: `tests/handles.rs`, all 7
  tests — stale handle after `destroy_node` fails `StaleHandle` across every
  one of 15 operations in one test; cross-document handles fail
  `WrongDocument` even when index/generation coincide, both for a read and
  for a mutation (leaving the target tree unchanged, snapshot-diffed);
  generation reuse stales the old handle without affecting the new one;
  post-`close()` every handle (including descendants and the root) fails
  `DocumentClosed`, not `StaleHandle`; `adopt_node` stales every descendant
  handle, not just the root; a kind-typed downcast on the wrong kind fails
  `WrongKind`. No `panic!`/`unwrap`/`expect` exists anywhere in
  `crates/dom/src/**`.
- **Insert/remove/replace/adopt/clone maintain tree invariants**:
  `tests/mutation_invariants.rs`, 16 tests — re-parenting detaches exactly
  once (no duplication); cycle rejection leaves the tree byte-for-byte
  unchanged (both children lists and revision counter); bad
  reference/child returns `NotFound`; `replace_child` preserves sibling
  position and leaves the old handle valid-but-detached; the two
  security-review self-aliasing edge cases and the sole-Element-child swap
  edge case are each covered by a dedicated test; `adopt_node` preserves
  subtree structure/content deep-equal and re-interns a custom (non-static)
  atom in the destination; shallow vs. deep clone correctness; Document's
  at-most-one-Element/at-most-one-DocumentType constraints; namespace-aware
  element creation and empty-name rejection (M2-T04 dependency);
  `revision()` strictly increases on success, unchanged on `Err`; a
  ~50,000-deep legitimate insert succeeds while a >100,000-deep one fails
  closed without leaking memory; a 500-step fixed-seed LCG-driven fuzz
  sequence cross-checked against a plain `HashMap`-based reference parent
  model (every accepted move matches the model, every rejected move really
  was a would-be cycle per the model).
- **Document teardown releases accounted memory without lingering
  references**: `tests/teardown.rs`, 8 tests — `close()` reports zero
  `node_count`/`bytes_estimate`; every pre-close handle (element, text,
  comment, root) uniformly fails `DocumentClosed`; 20 documents x 50 nodes
  created and closed in a loop show zero cross-document accumulation and
  exactly 20 `on_document_teardown` calls with zero `on_node_freed` calls
  (bulk teardown is not a per-node loop); scope-drop without an explicit
  `close()` still tears down and fires teardown exactly once; `close()`
  called twice is idempotent; `destroy_node` reclaims a detached childless
  node and fires `on_node_freed` exactly once, refuses an attached or
  non-childless node; `adopt_node` fires one `on_node_freed` per freed
  subtree slot individually. No `Rc`/`Arc`/raw pointer is used for tree
  structure anywhere in the crate (grep confirms), so this is a structural
  guarantee, not just tested behavior.

## Risks / follow-ups for the next task

- **M2-T06/T07 (V8 bridge)**: must key any wrapper cache by the full
  `(NodeIndex, Generation, DocumentId)` tuple, never `NodeIndex` alone (an
  index-only cache would silently hand out a stale wrapper across slot
  reuse). Must decide how to handle `adopt_node`'s JS-identity limitation

  identity preservation at the binding layer using the new
  `NodeChange::Adopted` signal.

  finalizer once a wrapper for a detached node becomes unreachable; nothing
  in `crates/dom` calls it automatically (by design — this crate has no GC
  of its own).
- **M2-T04 (tree builder)**: `create_element_ns`/`element_namespace`/
  `create_document_type` are implemented and tested but not yet exercised
  by a real HTML parser; M2-T04 is the first real caller.

  unenforced (deviation 7); if M2-T04's parser or a later consumer needs
  spec-exact ordering, that constraint belongs at the call site or as a
  follow-up to this crate.
