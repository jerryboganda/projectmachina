## Summary of what was implemented

New crate `crates/network` (`machina-network`), added to root `Cargo.toml`
`[workspace] members`. Own private Tokio runtime; synchronous public API
(`NetworkClient::fetch`) built on internal `async`/`await`. Modules:

- `url.rs` — `NormalizedUrl` on top of the WHATWG `url` crate: scheme
  allow-list (http/https only), canonical host extraction (never raw
  authority text), embedded-credential detection, fragment stripped from
  the wire request-target, redirect-`Location` resolution against a base.
- `address_class.rs` — `classify(IpAddr) -> DestinationClass` covering the
  full security-review table: loopback, link-local, cloud metadata (AWS
  IMDS v4/v6, Alibaba), RFC1918 private, unique-local IPv6, CGNAT, reserved
  (0.0.0.0/8, TEST-NETs, 240/4, 2001:db8::/32), multicast, broadcast,
  unspecified — including recursive reclassification through IPv4-mapped
  IPv6 (`::ffff:a.b.c.d`) and NAT64 (`64:ff9b::/96`).
- `ports.rs` — WHATWG Fetch "bad port" block-list (cross-protocol
  smuggling defense).
- `policy.rs` — `NetworkPolicy` trait (`evaluate_url` /
  `evaluate_resolution` / `evaluate_connect`), `RequestMeta`,
  `PolicyDecision`, and the built-in fail-closed default
  `DenyPrivateNetworks`.
- `dns.rs` — `Resolver` trait, `SystemResolver` (default, explicit
  full-answer-set resolution via `tokio::net::lookup_host`), and a
  `StaticResolver` test double (`test-support` feature).
- `connector.rs` — resolve → `evaluate_resolution` (full answer set) → pin
  one `IpAddr` → `evaluate_connect` → TCP connect → optional TLS handshake;
  the single pinned address is the only one ever dialed (DNS-rebinding
  TOCTOU defense).
- `tls.rs` — `rustls` `ClientConfig` builder, `webpki-roots` default trust
  store, `TrustStoreSource` enum (custom bundle reserved, not wired to any
  page/agent-controlled input).
- `body.rs` — `ResponseBody`: guarded raw reads (`DeadlineGuardedBody`,
  §"deadline/cancellation/idle timeout" below) → optional streaming
  decompression (gzip/zlib/brotli via `async-compression`) → incremental
  absolute-size/ratio/budget metering (`meter_stream`, `async-stream`).
  Implements `http_body::Body` directly; exposes `next_chunk_blocking` and
  the single named `read_to_end_bounded(max_bytes)` buffered helper.
- `client.rs` — `NetworkClient`: the manual redirect loop (every hop
  re-enters `evaluate_url`/`evaluate_resolution`/`evaluate_connect`),
  method/body rewrite rules (303→GET+empty; 301/302 POST→GET+empty;
  307/308 preserve), cross-origin/downgrade sensitive-header stripping,
  redirect count cap + loop detection, HTTP/1.1 always for plaintext,
  opportunistic HTTP/2 when TLS ALPN negotiated it.
- `runtime.rs` — `guarded()`: races any future against `ctx.deadline` and a
  25ms cancellation poll of `machina_command_bus::CancellationToken`.
- `error.rs` — crate-local `NetworkError` (no dependency on
  `machina-command-model`; native-core owns the `CanonicalErrorCode`
  mapping later, per the design).

  chunked test also drives `next_chunk_blocking` directly chunk-by-chunk).

## Explicit scope decisions (not silent shortcuts)

1. **No connection pooling / reuse across `fetch()` calls, and no connection-concurrency cap.** The design (§3) wants one pooled `NetworkClient` per `Session`. This pass connects fresh per hop and does not reuse connections across separate `fetch()` calls, and does not cap concurrent connections. Rationale: implementing a correct, safe pool (idle-timeout eviction, half-closed detection, per-origin keying bound to the *validated* IP, concurrency caps) is materially more code and risk than the milestone's stated acceptance criteria require (redirects/compression/chunking/cancellation/policy-rejection/streaming — none of which require pooling to demonstrate), and the security review does not list pooling itself as a `[NOW]` item. The `Connector`/`NetworkClient` boundary is structured so pooling and a concurrency cap can be added later without changing the public API (`fetch()`'s signature and `NetworkPolicy`/`RequestBudget` traits do not change). **This is a real functional/perf gap, distinct from a security gap** (every connection, pooled or not, still goes through the full per-hop policy pipeline) — recommend a follow-up task before production traffic volume, tracked here since I cannot write to `agents/BLOCKERS.md` (explicitly prohibited path for this task; see the note at the end of this file).
2. **HTTP/2 is opportunistic-only via TLS ALPN**, matching the design's stated scope ("HTTP/2 TLS-ALPN-only, opportunistic"). Plaintext HTTP always uses HTTP/1.1 (no H2C). Implemented (not deferred) — `client.rs::send_one_request` branches to `hyper::client::conn::http2` when the connector's TLS handshake negotiated `h2` via ALPN.
3. **Request bodies are pre-buffered `bytes::Bytes`**, not streamed. This is unrelated to the acceptance criterion "bodies stream without mandatory full buffering," which is about *response* bodies. Request bodies for the navigation/form-submission flows this loader serves are small; buffering them once makes 307/308 redirect replay trivial (no `RedirectBodyNotReplayable` failure mode needed). Documented in `request.rs`.
4. **No cross-crate change to `machina-command-bus` or `machina-session` was needed.** The design flagged two possible follow-ups:
   - *`CancellationToken` gaining a `Notify`-based wakeup* — not done. The design's own documented fallback (poll `is_cancelled()` on a short interval inside the same `select!` used for the deadline) is fully sufficient and is what `runtime.rs::guarded` and `body.rs::DeadlineGuardedBody` use (25ms poll interval — cancellation-to-abort latency is bounded and low without any change to `command-bus`).
   - *`Session::account_bytes(&mut self, n: u64)` split out from `account_request(bytes)`* — not needed. Reading the **current** `crates/session/src/lib.rs` (this task's instruction to verify against the current API, not the design doc's possibly-stale references) shows `Page::account(kind: PageResourceKind, amount: u64)` already accumulates incrementally on every call (`self.usage.set(kind, current + amount)` with a hard-limit check each time) — calling `account(PageResourceKind::NetworkBytes, n)` once per chunk already gives exactly the per-chunk budget semantics the design wanted, with zero API changes. `crates/network`'s own `RequestBudget::account_bytes(n)` trait method (crate-local, no dependency on `machina-session`) is the seam `native-core` will implement over `Page::account` when it wires the two together (M2-T09, per the design — out of this task's scope).
   Net result: **zero lines changed outside `crates/network/**`, root `Cargo.toml`, `security/requirements.json`, `tests/fixtures/manifest.json`, and `scripts/test/*` (fixture infra).** No other crate's source was touched.
