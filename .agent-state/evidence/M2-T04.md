## What shipped

- **`InsertionMode`** (`src/modes.rs`): the full 23-variant WHATWG
  §13.2.4.1 enum, doc-commented with spec anchors, plus `Dispatch::{
  Consumed, Reprocess}` for the bounded non-recursive dispatch loop.
- **`OpenElementsStack`/`ActiveFormattingElements`** (`src/open_elements
  .rs`, `src/active_formatting.rs`): built directly on `machina_dom
  ::ElementHandle` per design §2 — each entry caches tag/namespace (and,
  for AFE entries, the original token's attribute snapshot) so scope
  checks and AAA never round-trip through the DOM. Implements every scope
  kind (`has_in_scope`/`_in_list_item_scope`/`_in_button_scope`/
  `_in_table_scope`/`_in_select_scope`), implied-end-tags (plain and
  "thoroughly"), and the Noah's Ark clause.
- **Foster parenting** (`src/foster_parent.rs`): one shared targeting
  function consumed by `InTable`/`InTableText`/`InCaption`/`InTableBody`/
  `InRow` and reused inside the adoption agency algorithm, per design §3.
- **Adoption agency algorithm** (`src/adoption_agency.rs`): a structural
  implementation of the WHATWG steps with the spec's own fixed loop bounds
  (outer ≤ 8, inner ≤ 3) enforced as literal counter checks, and
  handle-based re-resolution at every step (never a raw index carried
  across a stack mutation) so a mid-algorithm mutation cannot desync into
  an out-of-bounds access. **Honest scope note**: verified against the
  common single-mismatch case and several representative misnesting
  shapes (see Test coverage below); **not validated against the full
  html5lib-tests `adoption01.dat`/`adoption02.dat` corpus**, which does not
  exist in this repository (no WPT harness has been built by any task
  through M2-T04).
- **Foreign content** (`src/foreign.rs`, `src/special.rs`): `<math>`/`<svg>`
  create namespaced elements via `create_element_ns`; a small SVG tag-case
  table handles the common camelCase names (`foreignObject`, `clipPath`,
  ...). **MVP simplifications, disclosed explicitly**: HTML-integration-
  point/MathML-text-integration-point re-entry into ordinary HTML
  insertion-mode rules mid-foreign-subtree is **not wired in** (the
  predicates exist and are unit-tested in isolation, ready for a follow-up
  pass); namespaced foreign attributes (`xlink:href` and similar) are not
  specially handled (no test exercises them) since `machina_dom
  ::AttributeMap` is namespace-agnostic per M2-T05's own note.
- **Tokenizer text-content-state bridge** (`src/builder.rs`'s
  `switch_to_text_mode`/`generic_raw_text_or_rcdata`): drives
  `Tokenizer::switch_to` exactly per design §5's table (`title`/`textarea`
  → Rcdata, `style`/`xmp`/`iframe`/`noembed`/`noframes` → Rawtext,
  `noscript` → Rawtext only when scripting is enabled, `script` →
  ScriptData, `plaintext` → Plaintext one-way), restoring `original_mode`
  on the matching end tag.
- **Script checkpoints** (`src/checkpoint.rs`, `builder.rs`'s `feed`/
  `finish`/`resume_after_script`): exactly the design §6 contract.
  `TreeBuilder` never owns `Document`/`Tokenizer`; every `</script>`
  closing an HTML-namespace `<script>` unconditionally produces a
  `ScriptCheckpoint` with the element and its (already-built) text child;
  `AlreadyPaused`/`NotPaused` are real, tested, typed errors; any `Ok`
  outcome leaves the builder resumable, `Err` (`Internal`) poisons the
  instance (checked via `check_not_poisoned` at the top of every driving
  method) — matches "malformed HTML never produces `Err`" exactly, since
  every production `Err` path in this crate is a `DomError` the tree
  builder believed unreachable, not a malformed-input path.
- **Defensive patterns (design §7, all six sub-points)**:
  - **(a)** `TreeBuilderLimits::max_open_elements_depth` (default 4,000)
    is asserted `< machina_dom::MAX_ANCESTOR_WALK` (100,000) both as a
    `debug_assert!` at every `TreeBuilderLimits::default()` construction
    and as a dedicated unit test (`src/limits.rs`) and integration test
    (`tests/adversarial_nesting.rs`).
  - **(b)** The ceiling is checked in `create_and_insert_element` **before
    any DOM call** — hitting it records `Diagnostic::NestingLimitExceeded`
    and returns `Ok(None)` without ever calling `Document::create_element_ns`
    for the offending tag; parsing continues under the current stack.
  - **(c)** Every DOM call the tree builder believed valid maps its `Err`
    to `TreeBuilderError::Internal(...)` via `self.poison(...)`, which sets
    `poisoned = true`; every subsequent driving call fails fast with
    `TreeBuilderError::Poisoned` rather than attempting a "recover from the
    recovery algorithm" retry.
  - **(d)** AAA's loop bounds are the spec's own fixed constants (§3).
  - **(e)** Implicit-close cascades (`pop_implied_end_tags`, `pop_until_*`)
    only ever shrink the open-elements stack.
  - **(f)** Dispatch is one non-recursive `loop { match mode { ... } }` in
    `builder.rs::dispatch`; "reprocess under a different mode" is
    `Dispatch::Reprocess`, bounded by `max_reprocess_hops` (default 8) and
    enforced as a literal counter check that poisons the instance if
    exceeded (this bound was never hit by any fixture in this crate's test
    suite — it exists as a structural backstop, matching the DOM crate's
    iterative `clone_node` and the tokenizer's flat-FSM posture one layer
    down).

## Deliberate simplifications and known gaps (disclosed, not silent)

- **`InFrameset`/`AfterFrameset`/`AfterAfterFrameset`**: minimal, safe
  handling (structural `frameset`/`frame`/`noframes` tags work; everything
  else is ignored with a recorded `Diagnostic::TokenIgnored` rather than
  silently miscompiled into ordinary `InBody` rules). Frameset documents
  are rare in modern content and were not prioritized for this pass — no
  test exercises frameset documents beyond confirming the crate doesn't
  panic/poison on frameset-shaped input (not currently asserted directly;
  flagged here as a real gap for a follow-up pass, not claimed as tested).
- **Template contents**: per WHATWG, a `<template>` element's children
  belong to a separate "template contents" `DocumentFragment`, not the
  `<template>` element itself. This crate appends template children
  directly under the `<template>` element (`machina_dom` has no
  per-element auxiliary-fragment concept to model the spec's exact
  structure without a `crates/dom` API addition, which was out of this
  task's narrow-exception scope since it wasn't a flagged M2-T05 gap).
  `InTemplate`'s structural-tag mode-reset rules (caption/colgroup/tbody/
  col/tr/td-th) are implemented; deep template-mode-stack correctness
  beyond that is not exhaustively tested.
- **Foreign-content integration points**: see "What shipped" above —
  predicates exist, re-entry is not wired in.
- **`new_fragment`**: implemented as a one-time insertion-mode seed from
  the context tag (select/table/tbody-thead-tfoot/tr/td-th/head/html
  cases), not the full dynamically-re-run "reset the insertion mode
  appropriately" algorithm the spec invokes at additional points (e.g.
  after certain table-cell-closing operations). No test exercises
  `new_fragment` directly — it compiles and follows the documented
  contract, but is unverified beyond that. Flagged as a real gap.
- **Document child relative-ordering** (DocumentType before Element)
  inherits M2-T05's own disclosed, intentional limitation (not enforced);
  this crate's own insertion order (DOCTYPE, then `<html>`) naturally
  produces spec-correct ordering for ordinary documents regardless.
- **`is_special` (§13.2.4.2)**: a representative, hand-transcribed list of
  the ~80 HTML "special" tags plus the MathML/SVG entries, not
  auto-generated from the spec — a transcription error here would be a
  latent correctness bug in AAA's furthest-block search and the "any other
  end tag" algorithm. No test specifically audits this list against the
  spec's own table (deferred to WPT infrastructure, which would catch this
  class of error via corpus differential).
