## Implemented and verified

- `crates/session/src/lib.rs` (foundation layer, no protocol/control-plane
  imports — only `machina_command_bus::CancellationToken`):
  - `SessionId`, `ContextId`, `PageId` canonical identities.
  - A single `LifecycleState` shared by sessions, contexts, and pages (typed
    aliases `SessionState`/`ContextState`/`PageState` kept for source
    compatibility), with one canonical transition table: create
    (`Creating -> Ready`), close (`Ready -> Closing -> Closed`), and an
    explicit cancel path (`Creating|Ready -> Failed -> Closed`) distinct from
    graceful close.
  - `Session` owns `Context`s; `Context` owns `Page`s. `Session` enforces
    session-level bounded counters (`max_contexts`, aggregate `max_pages`
    across all contexts) as hard limits (`ResourceLimitExceeded`).
  - `Page` owns six bounded resource categories with per-category hard
    limits: `DomNodes`, `Timers`, `EventListeners`, `NetworkRequests`,
    `NetworkBytes`, `Artifacts`. `Page::account` is atomic (usage is
    unchanged on rejection) and uses `checked_add` (no silent wraparound).
    `Page::release` frees capacity for the three point-in-time categories
    (`DomNodes`/`Timers`/`EventListeners`) and explicitly rejects release for
    the three cumulative categories instead of silently under-reporting
    usage.
  - Cancellation cascades top-down: cancelling/closing a `Session` cascades
    into every owned `Context`, which cascades into every owned `Page`
    (`cascade_cancel`), so no child is left orphaned or silently still
    running after a parent closes/cancels.
  - `Session::close_context` closes every page the context still owns before
    removing the context (fixed an initial bug where the aggregate page
    counter was decremented after the pages were already removed from the
    map, which would have under-counted; caught before commit by adding
    `closing_a_context_with_open_pages_closes_them_and_updates_aggregate_usage`).
  - 11 unit tests covering: canonical create/close/cancel transitions at
    every identity level, cascading cancellation, session-level context/page
    hard limits, every page resource category's hard limit, releasable vs.
    cumulative release semantics, resource accounting requiring a ready
    page, invalid-transition rejection at every level, and context close
    with open pages.

- `crates/native-core/src/lib.rs` (native engine composition):
  - Added the `EngineSession` facade: the per-session object that composes
    an engine identity (`Native`/`Chromium`) with a `machina_session::Session`
    (and therefore its contexts/pages/lifecycle/cancellation/resource
    counters). It consumes only canonical `machina_session`,
    `machina_command_model`, and `machina_capability` types — no
    protocol-adapter or control-plane type is imported or referenced.
  - `LifecycleEngine` (shared by `NativeEngine` and `ChromiumEngine`, as
    before) now stores `EngineSession` instead of a bare `Session`. The
    existing `session.create.v1`/`session.close.v1` command-bus behavior is
    unchanged in observable shape (`"session ready"`/`"session closed"`,
    same `CanonicalErrorCode`s); `session.close.v1` now explicitly documents
    and relies on cascading cancellation of any owned contexts/pages via the
    session-crate `transition` cascade.
  - Context/page create/close/cancel and resource accounting are **not**
    reachable through a canonical `CommandKind` yet — the command schema
    (`schemas/command-model/v0.1/command-model.json`) has no
    `context.create.v1`/`page.create.v1`/etc. defined, and this task's scope
    explicitly forbids inventing new protocol-layer types. These operations
    are therefore exposed as direct, symmetric Rust methods on both
    `NativeEngine` and `ChromiumEngine` (`open_context`, `close_context`,
    `open_page`, `close_page`, `account_page_resource`,
    `release_page_resource`, `cancel_session`, `health`), ready to be wired
    to those commands once the schema defines them. No new capability id is
    registered in the `CapabilitySnapshot` for these operations, since they
    are not reachable through `CommandBus::execute` yet and registering them
    would overclaim typed-command support.
  - `ChromiumEngine` composes context/page identities and resource
    accounting through the identical `LifecycleEngine`/`EngineSession` path
    as `NativeEngine` (pure bookkeeping, not a browser process). Chromium's
    actual browser launch remains the pre-existing explicit
    unsupported-capability boundary (`DispatchError::unsupported` for any
    `CommandKind` other than session create/close); this task does not fake
    that a Chromium page was rendered.
  - Added `EngineHealth`/`SessionHealth` types and a `health()` method on
    both engines: capability snapshot (`CapabilityResponse`) plus per-session
    lifecycle state, context/page counts, and resource usage/budget — the
    "capability snapshot and health exposed to worker/scheduler" deliverable.
  - `map_session_error` centralizes `SessionError -> DispatchError` mapping
    onto canonical `CanonicalErrorCode`s (`SessionNotReady`, `SessionClosed`,
    `QuotaExceeded` for both session- and page-level resource-limit errors,
    `InvalidArgument` for identity/lookup/transition errors) — no ad hoc or
    invented error codes.
  - 8 unit tests: the 2 pre-existing session-lifecycle/unsupported-command
    tests (unchanged behavior, still pass) plus 6 new tests covering
    create/close/cancel transitions through the engine composition,
    cancellation cascading into blocked further resource accounting, forced
    budget exhaustion for every one of the 6 page resource categories,
    forced budget exhaustion for the session-level context/page counters,
    health exposing capability snapshot + session state, and native/Chromium
    symmetry of context/page composition.
